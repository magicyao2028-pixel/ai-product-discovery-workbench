# Prototype Fidelity

## Low fidelity

A low-fidelity prototype tests structure, information, sequence, and basic interaction intent. It answers questions such as:

- What screens or steps exist?
- What information must the user provide?
- What is the primary action?
- Which requirement justifies each screen?

v0.1 outputs this level: screen title, purpose, fields, primary action, and requirement links. It is comparable to a wireframe or flow sketch, not a finished interface.

## High fidelity

A high-fidelity prototype is much closer to the intended product experience. It usually specifies visual hierarchy, component states, realistic content, interaction details, responsive behavior, and often a design system. It is suitable for usability testing or developer handoff only after its assumptions have been reviewed.

## Boundary in this repository

The static website presents the portfolio case attractively, but the product prototype described inside it remains low fidelity. Visual polish on a case-study page does not convert an untested product flow into a high-fidelity validated prototype.
